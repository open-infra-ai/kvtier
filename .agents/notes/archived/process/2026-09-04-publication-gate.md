# Agent Note: 公开门槛——达成前不进入 open-infra-ai 状态注册表

Status: implemented
Archived: 2026-10-25

## Problem

本仓是 KV 分层存储的私有研究孵化器。上游源码阅读能支撑「实现如何工作」
的叙述，但替代不了性能数据；单卡 L2 微基准也不能外推多卡、L3、EAGLE
场景。若在没有可审计结果时进入公开作品集注册表，等于把未完成的研究
包装成作品。

## Decision

同时满足以下四条才转公开作品（README「公开门槛」为准）：

1. 完成至少一组真实 GPU 实验，并通过结果包审计；
2. 固定上游 commit、模型、硬件、启动参数与原始日志，证明结论可复现；
3. 获得至少一个外部可验证的上游结果（合入的 PR 或 maintainer 确认的
   复现/修复）；
4. 公开前移除个人绝对路径、发布命令草稿与已失效的上游状态描述。

达成前：不进入状态注册表，不适用组织链接写法与命名冻结（工作区
`AGENTS.md` 规则 6）；README 收敛为私有孵化器定位（commit `8965148`）。

## Alternatives considered

- **先公开挂着、证据后补** — 曝光更早最强；但没有审计过的结果包，
  公开叙述只能是源码阅读笔记，恰好是本仓要避免的。
- **不设门槛、做到哪算哪** — 最省事；但门槛本身就是防止半成品
  被当成作品引用的机制。

## Consequences

- **收益**：达到门槛时的公开是「证据驱动」，与作品集其他仓同一纪律。
- **代价**：孵化期内的进展对外不可见；门槛检查靠 README 约定自觉执行。
