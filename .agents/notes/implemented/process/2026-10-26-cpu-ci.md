# Agent Note: 增加 CPU-only 离线测试 CI

Status: implemented

## Problem

仓库只有 `verify-notes` 工作流；`make test` 的 14 项客户端与结果审计离线测试
依赖本地执行，改动 `workload.py` 或 `validate_results.py` 时没有远端反馈。
毕业门槛把 CPU-only CI 列为待补项，同时真实 GPU 门禁因没有自托管 runner 无法
直接上 CI。

## Decision

新增 `.github/workflows/ci.yml`，在 `ubuntu-latest` 上执行 `make test`。测试只
依赖标准库与 `requests==2.31.0`（由测试内的假服务器/夹具覆盖），不需要安装
SGLang、模型或 GPU；`Makefile` 在缺少 `.venv` 时回退系统 `python3`。

## Alternatives considered

- **把测试并入 `verify-notes.yml`**：减少一个 workflow，但笔记校验与基准正确性
  的失败语义不同，分开更易定位。
- **在 CI 安装 SGLang 并跑真实服务**：托管 runner 无 GPU，安装体积 8 GB 级，
  只会得到不可靠的 skip 或超时。
- **只做语法检查**：成本更低，但无法覆盖结果包 schema 与服务端计数器聚合逻辑。

## Verification

本机 `make test`：14 项通过（0.005 s），并运行结果包审计样例
（`20260828T000000Z`，trials=1，paired_ttft_ratio_median=2.0）。远端 CI 在
推送后首次运行验证。

## Consequences

CPU 侧改动有远端门禁；CI 绿色不代表 GPU 回载、HiCache 行为或性能结论，真实
实验仍按 PLAN 的 GPU 门槛与结果包审计执行。
